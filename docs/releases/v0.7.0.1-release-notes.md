# Release Notes - v0.7.0.1

**Release Date**: September 14, 2026  
**Type**: Patch / Feature / Security  
**Scope**: Table & Excel Ingestion, Table-Aware Chunking, Table SQL Analytics, Rich Graph, Web Search Providers, Prompt-Injection Screening

---

## Overview

QueryMind v0.7.0.1 addresses tabular data ingestion (Excel `.xlsx`/`.xls`, CSV `.csv`, Word `.docx` embedded tables), eliminates column hallucination during long-table RAG retrieval via **Header-Preserving Chunking**, and adds exact SQL analytics over ingested tables, typed graph entities with community summaries, pluggable web-search providers and prompt-injection screening. A pre-merge review on 2026-09-14 fixed fourteen defects in that work, four of them isolation failures; see [Pre-merge Review Fixes](#9-pre-merge-review-fixes-2026-09-14).

---

## Key Highlights

### 1. Unified CSV & TSV Tabular Ingestion
- **Frontend & Backend Upload Authorization**: Added `.csv` to `ACCEPTED_UPLOAD_EXTENSIONS` in `frontend/src/lib/uploadFormats.ts` and `limits.supported_suffixes` in `app/api/routes/public/documents.py`.
- **Adaptive Delimiter & Encoding Sniffer**: Built `_csv_rows` in `app/ingestion/loaders/office_loader.py` supporting UTF-8 (with BOM), GB18030, GBK, and Latin-1, with automatic dialect detection (comma, semicolon, tab, pipe).
- **First-Class Table Evidence**: Produces structured `TableBlock` records with `modality="table"`, indexed automatically into Chroma's dedicated `table_summaries` collection.

### 2. Table-Aware Header-Preserving Chunking (Anti-Hallucination)
- **Problem**: Previously, when long tables exceeded chunk boundaries, subsequent child chunks (chunks 2, 3, etc.) lost their header rows, causing severe LLM hallucinations and column transposition during retrieval.
- **Solution**: Implemented `_split_markdown_table_text` in `app/ingestion/chunking/splitter.py`. Every sliced child chunk now retains:
  - Header line (`| Col 1 | Col 2 | ... |`)
  - Alignment delimiter (`|---|---|...|`)
  - Row range metadata (e.g. `(Rows 16-30 of 60)`)
  - Sheet title label (`### Sheet: Sales_2024`)

### 3. Multi-Sheet Context Enrichment & DOCX Extraction
- **Explicit Sheet Demarcation**: Markdown tables automatically prepend `### Sheet: {sheet_name}\n\n` in `_rows_to_markdown`, eliminating confusion when workbooks contain multiple sheets with identical column names.
- **DOCX Pipe Table Extraction**: `extract_markdown_tables` parses pipe tables from Word `.docx` documents into `TableBlock` instances for multimodal retrieval.
- **Enriched TableExtractor**: Formats column schema lists, total row counts, and sheet metadata into ChromaDB vector records.

### 4. Excel Merged-Cell Forward-Fill & Large Table Guardrails
- **Forward-Fill Merged Cells**: `_extract_sheet_rows_with_merged_cells` in `office_loader.py` resolves `sheet.merged_cells.ranges`, populating the top-left value across all rows in the merged range so subordinate rows retain their department and category labels.
- **Row-Count Safety Cap**: `MAX_TABLE_ROWS = 5000` with markdown truncation notices, reported only when rows were actually cut.
- **Merged-Range Guard**: the declared merged area is read from the archive before openpyxl loads the workbook in full mode; past 200,000 cells, or for files over 20 MB, the workbook is streamed read-only and merged cells are not filled.

### 5. Universal Non-Office `TableBlock` Extraction (PDF & Markdown)
- **Extensible Extraction in Dispatch**: `load_document_with_evidence` in `dispatch.py` now parses markdown tables from PDF and Markdown files into `TableBlock` records with unique IDs, ensuring non-Office tables are indexed into Chroma's `table_summaries`.

### 6. Tabular Business Query Routing & Nested Table Normalization
- **Routing Expansion**: `_VISUAL_QUERY_PATTERN` in `service.py` recognizes business vocabulary (`excel`, `csv`, `xlsx`, `tsv`, `spreadsheet`, `sheet`, `报表`, `明细`, `清单`, `台账`, `账单`, `数据表`).
- **Nested Table Bugfix**: `tables_nested.py` fixes regex cell extraction using negative lookbehind `(?<!\\)\|` and strips embedded HTML tables cleanly.

### 7. Table SQL Analytics
- **`querymind_table_query`** (a governed read tool) runs SQL or natural-language aggregations over an ingested table through `TableStore` / `TableEngine` (`app/services/tables/`), DuckDB with a SQLite fallback.
- **Owner-scoped**: a table is readable only by its document's owner, or when the document is public or in the shared corpus; anything else is reported as not found.
- **Persisted**: tables and their ownership are stored in SQLite, so they survive restarts and every worker answers the same; engines are a bounded cache rebuilt from the database.

### 8. Rich Graph, Web Search Providers & Injection Screening
- **Graph**: typed entities with per-source descriptions, community detection and global search, `POST /admin/graph-rag/communities/build`, a full-text entity index.
- **Web search**: `WEB_SEARCH_PROVIDER` selects `duckduckgo`, `tavily`, `bing` or `searxng`, with proxy, timeout and retry settings; the chat composer gains a web-search toggle.
- **Prompt injection**: input screening, nonce-sandboxed prompts, canary tokens and output egress checks (`app/services/security/injection_defense.py`).

### 9. Pre-merge Review Fixes (2026-09-14)
- **Table isolation**: owner-scoped reads, one in-memory engine per table (a shared engine let `SELECT * FROM tbl_a, tbl_b` read a colleague's table), tables dropped with their document.
- **DuckDB**: opened with `enable_external_access=false`; table functions that reach files, other databases or the environment are refused. Verified on duckdb 1.5.5.
- **Graph**: descriptions and community summaries are attributed to their source and returned only inside the reader's scope; retrieved documents no longer choose which entities the graph looks up.
- **Injection detector**: no longer blocks ordinary questions (Android developer mode, detecting `vssadmin delete shadows`, `rm -rf` risks, a colleague named Dan, `.gitignore` rules).
- **Security defaults** restored: `AUTH_EXPOSE_TOKEN_IN_RESPONSE=false`, `AUTH_COOKIE_SECURE=true`, `AUTH_COOKIE_SAMESITE=strict`. Provider API keys and URLs are not editable from the admin console.
- **Honest failures**: a failing model provider is reported as a failure rather than answered by the offline stand-in; the chat vector path has no relevance-score floor.
- **Runtime**: blocking calls moved off the event loop; the planner's retrieval budget is respected; web-provider settings take effect on config reload.
- **SonarCloud**: quality gate green. The markdown table-separator pattern and nine other regular expressions over document text no longer backtrack super-linearly (one took 8.4 s on a single line of 2,000 spaces); each rewrite is pinned against the previous pattern over generated inputs.

## Upgrade Notes

- **Graphs written by a pre-release build** keep descriptions on the entity node and relationship, where nothing reads them now. Reingest the affected documents, or call `POST /admin/graph-rag/communities/build`.
- **`duckdb>=1.0.0`** is added to the `office` and `multimodal` extras.
- **SQL-queryable tables are persisted** to a new `structured_tables` table in `APP_DB_PATH`, created on first use. Tables ingested by a pre-release build were held in memory only; reingest those documents to make their tables queryable.
