# Release Notes - v0.7.1.1

**Release Date**: September 29, 2026  
**Type**: Patch / Frontend & Request Flow  
**Scope**: Answers name the specialist that wrote them and number their tool sources; the chat, architecture, landing and analytics pages describe the pipeline as it runs; fewer model calls per question; defensive security questions are answered instead of refused

---

## Overview

v0.7.1 added five domain specialists. This patch makes them visible where the
reader looks, and removes friction a review of the whole request path -- from
the chat box to the saved answer -- found between the question and its answer.

---

## Key Highlights

### 1. Every answer says who answered it, and how

- **Every answer used to be reported as the general analyst.** `RAGPipeline`
  never copied the route's specialist and skill into its result, so the chat
  response, the re-run record and the analytics log all saw "general". The
  chat response now carries `agent_class` and `skill` (the answer shape), and
  the badge reads, for example, "网络安全 · 漏洞暴露评估" / "Cybersecurity ·
  Exposure assessment".
- **The tool panel numbers its tools the way the answer does.** Each cited tool
  result carries the `T{k}` the answer's **Tool sources** list uses, so `[T1]`
  in the text points at exactly one row; tools show friendly names in both
  languages.
- A fresh answer keeps its source badges instead of showing "no sources" until
  the page is reloaded.

### 2. The pages describe the system as it is

- **Chat page**: the specialist count is derived (5, it read a literal 4); two
  new tiles (domain specialists, cited tool results); starter questions follow
  the selected mode, and Auto shows one per specialist; follow-up suggestions
  use the specialists' tools; the PDF card is now **Document Reading**.
- **Architecture page**: the six pipeline steps describe the real nodes (it
  claimed sandboxed calculators and APIs, "1-5 req/h" and "5 tool rounds");
  KPIs show 5 domain specialists and 160 endpoints; the calculation demo is the
  data-analysis specialist it depicted; the API catalog is rebuilt from the live
  OpenAPI document (it listed endpoints that do not exist) and a test keeps it
  that way; the architecture diagram is redrawn from the pipeline.
- **Landing and analytics**: the document card and the tool-gateway pop-ups no
  longer claim a sandbox; per-specialist charts use specialist names.

### 3. Fewer model calls between a question and its answer

- **Clarification** asked the model about every question the rules found
  complete. It now does so only for a question too short to say what it is
  about, or an open-ended build/design/plan task.
- **Self-RAG** ran on every question, after the pipeline and outside its
  budget, so a slow run could make the browser time out while the server went
  on to save the answer. The chat client no longer requests it, and a caller
  that does gets only what the deadline leaves.
- **A retry replays only what can change**: retrieval that found nothing is not
  retried, and a retry keeps the first round's tool results instead of running
  the tools again (which could also mint a second approval token for one
  action).

### 4. Questions about attacks are answered

- "vssadmin delete shadows 被执行了怎么办？" was refused as a "dangerous
  instruction" -- a keyword rule read 被执行了 ("was executed") as a request to
  run it. The rule is removed; the intent-based injection check still refuses
  requests to *run* such commands.
- A refused question now answers **422 with the reason** instead of a 500.
- On the offline backend (a fresh checkout's default), clarification no longer
  asks every question which tech stack it plans to use.
- Re-running an edited message asks the question the chat path would: no
  appended "[补全提示]" instructions, reasoning off as in chat, and the
  conversation passed as the turns before the edited message.

## Upgrade

No configuration or data migration. Deploy as usual:

```bash
./deploy/scripts/deploy.sh production balanced
```

### API changes

- `POST /api/advanced-rag/query` metadata gains `agent_class` and `skill`, and
  each `tool_runs` entry may carry `marker` (`"T1"`, `"T2"`, ...) when the
  answer cites it. Additive; older clients ignore them.
- A question refused by input screening answers **422** (was 500).
- The chat client sends `enable_self_rag: false`. The API still accepts `true`,
  bounded by the request's `timeout_ms`.

### Development

- `QUERYMIND_API_TARGET` overrides the Vite dev server's backend target
  (default `http://127.0.0.1:8000`), for machines where Windows reserves that
  port.
