# Release Notes - v0.7.2

**Release Date**: September 29, 2026  
**Type**: Minor / API & Architecture (breaking API paths)  
**Scope**: Every endpoint moves under `/api/v1`; one execution stream; reliable document deletion with index reconciliation; session messages in their own rows; pushed server-sent events; frontend server state in a query cache

---

## Overview

This release closes the architecture items left open by the September audit.
Most of it is internal and backward compatible. One part is not: **every
application endpoint now lives under `/api/v1`, and the old paths are
removed.** Read the upgrade section before deploying.

---

## ⚠️ Breaking: one API prefix

The API had been spread over about twenty prefixes. Every application endpoint
is now `/api/v1/<same path>`:

| Before | After |
| --- | --- |
| `/sessions`, `/sessions/{id}` | `/api/v1/sessions`, `/api/v1/sessions/{id}` |
| `/auth/login`, `/auth/me`, … | `/api/v1/auth/login`, `/api/v1/auth/me`, … |
| `/admin/...` | `/api/v1/admin/...` |
| `/documents`, `/upload`, `/prompts` | `/api/v1/documents`, `/api/v1/upload`, `/api/v1/prompts` |
| `/user/active-model`, `/model-catalog` | `/api/v1/user/active-model`, `/api/v1/model-catalog` |
| `/optimization/...`, `/agent-tracking/...`, `/circuit-breakers` | `/api/v1/...` |
| `/api/advanced-rag/...`, `/api/analytics/...`, `/api/evaluation/...` | `/api/v1/advanced-rag/...`, `/api/v1/analytics/...`, `/api/v1/evaluation/...` |

- **Not moved**: `/`, `/health`, `/ready`, `/ready/dependencies`, `/metrics` and the web app under `/app`.
- **Removed, not deprecated**: the old paths answer 404. `/app/api/...` still works for a frontend served under a base path.
- **One live stream**: `GET /api/v1/orchestration/executions/{id}/events` is the only server-sent-events endpoint. The polling `/agent-tracking/stream/{id}` is removed.
- **One trace read**: `/api/v1/agent-tracking/trace/{id}` is the only trace read. The admin-only duplicate `/agents/trace/{id}` is removed.
- The API now has 158 operations.

## Key Highlights

### 1. A document delete that fails part-way is no longer reported as done

If one store refuses a delete, the uploaded file and its registry record are
kept, the record is marked `delete_failed`, and the request answers 503.
Retrying finishes the delete. `python -m app.services.documents.reconcile`
compares the corpus, the vector collections, structured tables, image and
table summaries, the knowledge graph and the registry, and reports anything
that drifted. `--repair` removes only derived orphans; it never deletes
documents or files. `INDEX_RECONCILE_INTERVAL_SECONDS` runs the check on a
schedule. It is off by default; the production example runs it every 6 hours,
report-only.

### 2. Conversations are stored message by message

SQLite is now the default history backend, and each message is its own row.
Appending a message writes one row instead of rewriting the conversation, and
the session list no longer reads message bodies. Existing JSON conversations
are imported automatically the first time each user's history is opened. The
original files are left in place.

### 3. Live events are pushed

In single-process mode, the answer stream is woken when there is something new
instead of polling every 50 ms.

### 4. Internals

- Per-run budget and callbacks are no longer part of the workflow state, which now holds only serializable data.
- Process-wide singletons share one helper; `global` statements went from 43 to 1.
- Frontend: the API layer has one import path, and sessions, documents and prompts are cached with TanStack Query. The cache is cleared on sign-out.

## Upgrade

1. **Back up `data/`.** Conversations are imported into SQLite the first time each user's history is opened.
2. **Update everything that calls the API**: scripts, n8n workflows, monitoring, and any separately deployed frontend. Old paths return 404.
3. **Google sign-in**: if configured, change the authorized redirect URI to `https://<host>/api/v1/auth/google/callback`.
4. **Custom nginx**: the unbuffered streaming location is now `location ~ ^/api/v1/orchestration/executions/[^/]+/events`. The repository's `nginx.conf` is already updated.
5. Optional: set `INDEX_RECONCILE_INTERVAL_SECONDS` to enable scheduled index checks. Leave `INDEX_RECONCILE_REPAIR` off until the reports have been clean for a while.
