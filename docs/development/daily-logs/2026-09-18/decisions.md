# 2026-09-18 技术决策 / Decisions

## 1. P@5 不是该被优化的对象，是该被正确报告的对象

单 gold 语料上 `P@5 == recall@5 / 5` 恒成立，它不携带 recall 之外的任何信息。
报告首位放 recall / MRR / nDCG，P@5 与 `precision_ceiling_at_k` 并排印。

**上限由标注算出，不写死。** 语料哪天多了一篇相关文档，上限自己上升——
一个需要人去改常量才会变的「理论上限」，下次就是过期的。

## 2. `complete@5` 而不是只看 recall

跨文档问题上 recall 是宽容的读法：两篇里找到一篇算 0.5。
但**半份证据不是半个答案，是一个自信的错答**——合成器拿到一半证据不会产出一半答案。

`complete@k` 在单 gold 集合上**恒等于 recall@k**，所以加它没有改动任何既有数字。
两者只在多 gold 时分叉，而那正是宽容读法开始掩盖问题的时刻。

**它统计所有 grade > 0 的文档，没有隐藏门槛**——等价于「recall@5 达到了 1.0」。
后果是写标注的规则：不需要的文档标 0（记录「看过、判过」），而不是标 1 当作可选。

## 3. 干扰文档标 `secondary` 而不是 `distractor`

加它们是为了在窄问题上当噪声；结果它们成了跨文档集合的 gold。
**相关性是「问题-文档」这一对的属性，从来不是文档的属性。**
`distractor` 是个全局断言，在跨文档集合存在的那一刻就成了假话。
`distracts` 保留，因为它说的是「干扰哪个查询」，这句仍然为真。

## 4. 全链路评测拒绝运行，而不是降级

重排模型和嵌入模型都以 `local_files_only=True` 加载，缺失时**不抛异常**——
退化成 `lexical_rerank` 和哈希嵌入，照常回答每个查询、照常印出一个数字。
空的 Chroma 目录通过数据造成同样的后果。

一个测错东西的绿色指标比没有指标更糟，所以退出码 2、一个数字都不输出。

四个附带决定：
- **问 `effective_model_configuration()`，不自己判断。** 它已经是「配置了」与「机器上有」
  之间唯一的裁决者，写第二套实现就是两个会在关键那天分歧的答案。
- **只要求 `embedding` 和 `reranker`。** 一个指着 Tesseract 的拒绝，人们的解法是把守卫关掉。
- **`disabled` 和 `degraded` 一样拒。** 关掉重排是合法配置，只是不是报告声称的那件事。
- **用带 scope 的真实 `similarity_search` 探库**，不用集合计数：存着别的租户 chunk 的库
  对这次运行就是空的，计数分不出这两种情况。

## 5. 跨文档集合单独成文件

主集合问「答案是不是排第一」，MRR 是它的指标；跨文档集合问「答案能不能从前五里拼出来」，
complete@5 是它的指标。混在一起，聚合数字哪个都不代表。

同样的理由决定了**每条题必须由同语言的文档回答**：BM25 跨语言零共享 token，
中文问题配英文 gold 必然得零——那测的是跨语言匹配，是另一个问题、另一个指标。

## 6. 路径容器放在 CLI 边界，不放在 `load_queries`

`--queries` 让命令行的值直达文件打开（`pythonsecurity:S8707`）。

不当成「自己的开发脚本」放过，理由仓库里已有先例：规则把风险描述为
「一个 agent 用它没有选择的参数运行这个工具」，而这正是这个仓库被操作的方式。

**先 resolve 再判断在不在树内。** `".." not in raw` 挡不住仓库内指向树外的软链接。
放在 `main()`：sink 是应用代码，测试合法地用自己的路径调它；而参数只有在跨过命令行时才不可信。

## 7. 文档写运行时打印的三个数，不写单一总数

`--collect-only` 报 2,474 项，运行报 2,475 个结果——差值来自 import 阶段就跳过的模块
（不贡献 item 但贡献一次 skip）和一个 id 里带时间戳的参数化用例。两个数都不错，
差值不是丢了测试。与其断言一个我没完全解释清的总数，不如写别人能复现的那一行。
