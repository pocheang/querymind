## 教训

**一、「验证能失败」这一步抓到的东西比写代码多。** 七个 commit 里有四个洞是变异测试
发现的，不是读代码发现的：

- 一条**恒真断言**：用 `complete_at_k([], ...)`（对任何 query 都返回 0）构造失败集合，
  再和它要检查的表求交集。只可能通过。
- 给 `missing` 单独加 `grade >= 3` 门槛，**零变红**——现有数据上两套规则恰好同解，
  会无声分叉。那种失败形状最糟：聚合说这题不完整，旁边的诊断一个名字都说不出。
- 把路径容器从 `main()` 拿掉，**零变红**——所有测试都直接调那个函数。
  **写了、测了、接不上。**
- 一个 `pytest.raises` 块里有两个可能抛异常的调用，错的那个抛了也算通过。

**二、我自己的标注错误比检索缺陷更早出现。** 跨文档集合第一版的 `x-07` 是中文问题配
英文 gold，BM25 跨语言零共享 token，必然得零。它测的是跨语言匹配而不是跨文档组装——
正是我在同一个文件的 readme 里反对的那种混淆。

**三、绿灯不等于没发现。** 质量门禁通过的那一轮同时报告了 2 New issues，其中一条是真的
（`pytest.raises` 那条）。读出来才知道。

**四、仓库自己的闸门抓到两件事**：新脚本 21 分超复杂度阈值，以及一个 docstring 承诺了
代码从不返回的退出码。
